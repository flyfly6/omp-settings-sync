# omp-settings-sync — Development Specs

> Coding guidance for this repository, written from the code that exists today.

---

## What This Project Is

A single-package Oh My Pi (omp) **extension** published to npm as `omp-settings-sync`. It treats the agent directory (`~/.omp/agent`, or `~/.omp/profiles/<profile>/agent`) as a git working tree and syncs the allowlisted parts of it through any user-supplied git remote. Encrypted credentials travel inside `vault.enc`; everything else that smells like a secret is refused by hard guards.

- Runtime: Node.js >= 22, ESM (`"type": "module"`), **zero runtime dependencies** — only `node:` builtins (`package.json` has no `dependencies` field, only `peerDependencies`).
- Sources: `src/` (9 modules, 2 569 lines). Build output: `dist/` (committed, generated by `tsc`, never hand-edited).
- Tests: `test/` with `node:test`, compiled to `dist-test/` by `tsconfig.test.json`.

## How To Use This

1. Read `plugin/index.md` — it holds the **Pre-Development Checklist** and the **Quality Check**.
2. Read the topic files it points to for the area you are touching.
3. Always skim `guides/index.md`; the multi-site change map there is the most common source of "forgot to update X" bugs in this repo.
4. Verification commands are `npm run typecheck`, `npm test`, `npm run check` (see `plugin/testing.md`).

## How These Specs Were Produced

Direct source reading of every module in `src/` and every file in `test/`, plus `package.json`, `tsconfig*.json`, `README.md`, and the git history. GitNexus and ABCoder were not available in this environment, so no graph-derived claims are included — every rule points at a file or symbol that exists in the tree.

Known limitations of the snapshot:

- Line counts and default values reflect the tree at the time of writing; verify against the file when a rule looks stale.
- The two unused knobs (`warnOnPublicRemote`, `shouldAutoSync`) and the missing vault `version` gate are documented as they are, not as they should be.
